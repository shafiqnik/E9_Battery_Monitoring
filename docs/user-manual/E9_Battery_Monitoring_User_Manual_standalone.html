1. What this tool does

E9 Battery Monitoring is a live web dashboard for Contigo E9 BLE tags. It listens to MQTT battery advertisements from the Dusun production farm, keeps tags that belong to a chosen gateway (CFC id), and shows battery %, online/offline state, dropouts, and suspected battery replacements.

It does not control tags. It is a read-only monitor. Refresh is automatic (about once per second). You do not need to log in to the web page.

Typical use: open the page on a PC on the same network, leave it running, and watch for Offline, Low Battery, Anomaly, or frequent dropouts.

2. How to open it

  1. Confirm the application is running on the Linux (or Windows) host.
  2. In a browser, go to http://<host-ip>:8081.
  3. On the machine that runs the app, http://127.0.0.1:8081 also works.

Use http, not https. The default port is 8081.

MQTT username and password are read from credentials.txt in the application folder. They are not entered on the web page. To change them, edit that file and restart the app.

Optional: start with a different gateway id:

./run_linux.sh 30AE7BE844CF
./run_linux.sh 30AE7BE844CF,AABBCCDDEEFF

3. Dashboard at a glance

Read the page top to bottom:

  1. Connection status and four summary counts
  2. Anomaly table (after you click the red card)
  3. Battery chart over time
  4. Every tag’s MAC, battery, and status
  5. Tags that should be reporting but are not
  6. How often each tag has gone offline
  7. Replacement funnel (0% → still empty → back to 100%)

6. Battery level over time

The header of this panel also shows the current clock and how long the app has been running (uptime).

  • Green line — normal. Battery should fall slowly over days, not bounce around.
  • Red line — that MAC already had an anomaly or a replacement event.
  • A flat 100% line (this capture) means tags are full. You will not see drain until they leave 100%. Readings at 100% are shown here but are not appended to batteryLevel.txt.

9. Offline tracking

A gap only increments times offline > 1 min if the tag stays quiet for at least 60 seconds. Short blips under a minute are ignored in that counter.

ColumnMeaningExample
ble_addrTag MACC3:00:00:99:01:18

Use this to find flaky tags, not just tags that are down right now.

  • C3:00:00:99:01:18 — online, 10 long dropouts, about every 2 hours
  • C3:00:00:99:01:19 — online in this capture, but 15 long dropouts, about every 1h 19m (noisier than its neighbours)

This table is written to offline_tags.txt and reloaded when the app starts, so history survives a restart.

10. Battery replacement detection

Read left to right. Click a step (except “Currently at 0%”) to open Anomaly details filtered to that event type.

StepMeaningThis capture
Drop to 0%How many times a tag fell from a positive % to 0%0
Currently at 0%How many tags’ latest reading is still 0%0
Return to 100%How many times a tag went from below 100% back to 100% (treated as a new battery)0
Event recordedTotal anomaly + replacement events. Click for the full audit list.0

Worked example of a real replacement sequence:

  1. Tag reports 18% … 7% … then 0% → Drop to 0% becomes 1, Currently at 0% becomes 1
  2. Technician swaps the cell
  3. Next frame is 100% → Return to 100% becomes 1, Currently at 0% returns to 0, Event recorded increases

11. Status meanings

StatusWhen you see it
OKHeard in the last 60s, battery ≥ 64%, no anomaly flag
LowHeard recently, battery < 64%
OfflineNo battery sample for more than 60s
AnomalyHad a drop to 0% or a ≥30% drop
ReplacementHad a jump back to 100%

The top status line should stay Connected to Dusun Production farm | live MQTT. If it stays on Connecting, or the page never leaves “Loading…”, MQTT is not up (broker, network, or credentials.txt).

12. What gets saved to disk

Files sit in the application folder (same place as main.py). Open them in Excel or a text editor. Columns are tab-separated.

FileWhen it is writtenWhat is in each line
batteryLevel.txtEvery parsed reading below 100%time, MAC, raw hex advertisement, battery %
anomalyEvents.txtDrop to 0%, sudden ≥30% drop, or return to 100%time, MAC, previous %, new %, kind, reason, raw hex
offline_tags.txtWhenever online/offline state changesMAC, offline-since or “online”, long-dropout count, how often, last seen, first seen, offline event count

The web page itself is not a log. HTTP access is not written. MQTT passwords are not written to these files.

13. Tips and troubleshooting

  • Page loads but counts stay 0 — MQTT connected but no messages match the CFC/gateway id. Confirm the id you started with (default 30AE7BE844CF).
  • Cannot open from another PC — use the Linux host IP and port 8081. If the app was bound only to 127.0.0.1, restart with E9_WEB_HOST=0.0.0.0. Firewall may still block 8081.
  • Chart.js fails to draw — the page loads Chart.js from the internet. A machine with no outbound web access will show tables but a blank chart.
  • Numbers look old after restart — expected. Battery history, anomalies, and offline counts reload from the three text files.
  • One tag keeps appearing in Offline tracking — that is a coverage or hardware issue, not a dashboard bug. Compare its “avg every …” to neighbouring MACs. In this capture, C3:00:00:99:01:19 dropped more often than …:18.
